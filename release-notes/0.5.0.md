# forge v0.5.0

> Changes since v0.1.0

## AI Scaffold & Tooling

- **Simplified `--ai` flag** — `forge update ./my-app --ai` now uses a single content-aware flag. Files are skipped when unchanged and updated only when the source differs. The previous `--ai-core`, `--ai-rules`, `--ai-skills`, `--ai-docs`, and `--ai-force` sub-flags have been removed.
- **Removed programmatic skill generation** — Claude skills are now exclusively static asset files, eliminating drift between generated and maintained skill content.
- **Community Skills config** — a configuration has been added so hosted skills can be referenced and deployed as part of scaffolding.
- **AI scaffold via `forge update`** — existing projects can now receive Cursor rules, Claude skills, `CLAUDE.md`, and `FORGE_RECOMMENDATIONS.md` via `forge update --ai`.
- **Skills and default settings in template** — new and updated projects now scaffold with Cursor rules and Claude Code skills out of the box.
- **Updated `git-pr` skill** — the PR skill now prompts for a Linear ticket number and appends a plain link to the PR body when provided.

## Developer Experience

- **GitHub, Vercel, and Supabase org picker** — `forge config` now lets you select your GitHub, Vercel, and Supabase organization from a list rather than typing it manually.
- **Improved version reporting** — `forge --version` now surfaces more accurate version information.
- **Cursor rules for the forge repo** — the forge repo ships with its own `.cursor/rules/` for consistent AI-assisted development on the tool itself.
- **Changed initial commit message** — scaffolded projects now use a cleaner initial commit message.
- **Updated landing page** — the deployed forge landing page has been refreshed.
- **Default Claude project config** — new projects include a default Claude project configuration.

## Bug Fixes & Stability

- **Template TypeScript errors fixed** — resolved type errors and warnings in scaffolded Next.js templates.
- **Launcher fixes** — fixed the forge launcher when Node.js is missing from PATH after a fresh install.
- **pnpm path resolution** — multiple fixes to handle pnpm path issues that required sourcing the shell on fresh installs; `install.sh` now sources the shell environment correctly.
- **Bootstrap improvements** — updated installer to handle Homebrew edge cases and support non-developer users with a guided setup flow.
- **`.env.example` cleanup** — the scaffolded `.env.example` is clean with no leaked secrets or placeholder values.

## CI & Quality

- **CLI smoke tests** — a GitHub Actions workflow runs a full end-to-end smoke test on every PR and push to `main`, scaffolding a real project and running `pnpm build` and `pnpm test` against it.
- **Lazy dependency loading** — CLI dependencies (Vercel CLI, Docker, Supabase CLI, etc.) are now installed on-demand rather than upfront, speeding up commands that don't need them.
- **Dependency version bumps** — updated core package versions across the scaffolded app template.
- **Public install script** — `install.sh` allows forge to be installed without cloning the repo via `curl -fsSL https://raw.githubusercontent.com/thicks/forge/main/install.sh | bash`.
- **Troubleshooting guide** — added a troubleshooting section to the README covering common pnpm and Node path issues.
